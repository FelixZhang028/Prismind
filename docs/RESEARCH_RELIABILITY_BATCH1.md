# 第一批：回测可靠性、股票池导入和研究记录归档

对应反馈 1、2、3、5。模拟账户数量和策略类型不在本批范围内。

## 用户可见行为

- 普通策略、规则策略、条件选股的历史回测通过后台任务执行。提交后返回任务编号，页面每两秒读取状态。
- 回测页和研究记录页显示排队、计算、取消中、完成、失败、超时；显示实际已处理交易日，不用等待时间模拟百分比。
- 刷新、切页或关闭浏览器不停止后台计算。任务链接保留编号；任务完成后可直接打开结果。
- 已排队任务可立即取消；运行中的任务通过停止独立计算进程取消。进程退出后才释放计算名额。
- 提交时保存股票池、过滤条件、风控、策略参数和规则定义。排队期间修改股票池或删除规则策略，不改变已提交任务。
- 股票池上限为 6000 只；超过上限整批拒绝，不截断。返回输入、新增、重复、无效和最终总数，并列出无效项和重复项。此处有效性是代码格式检查，不保证每只代码都已有行情。
- 条件选股每页 100 条，支持翻页，显示匹配总数及本页范围；分页不改变保存的股票池。
- 研究记录支持单条/批量归档、查看已归档和恢复。归档不删除回测结果、审计证据或关联数据。

## 运行方式与边界

- 沿用现有单 API 进程部署要求。队列存入 SQLite；调度器随 FastAPI lifespan 启停。
- 每人最多 5 个待完成任务，全站最多 100 个。执行并发沿用 `FELLOWQUANT_COMPUTE_SLOTS` 与 `FELLOWQUANT_COMPUTE_PER_USER`，同时计入原有重计算名额。
- 超时沿用 `FELLOWQUANT_COMPUTE_TIMEOUT`，默认 600 秒。从启动计算进程开始计时，不包括排队时间；父进程负责硬停止，不依赖引擎检查点。
- 服务重启后，原运行中任务标记失败并提示重新提交；尚未开始的任务保留排队。子进程监测父进程租约，避免 API 异常退出后遗留无限运行的计算。
- 成功结果和任务成功状态在同一数据库事务中发布。取消已取得锁时，迟到结果不能再发布。
- 活跃任务优先出现在列表中；同时显示最近任务。旧任务链接可按任务编号读取。
- 新增 `backtest_jobs` 表及 `backtests.archived_at` 字段，应用启动时自动迁移；已有记录默认未归档。
- 原同步后端接口保留兼容。当前前端回测入口使用新任务接口；参数优化、滚动验证、因子研究仍沿用原有计算方式。
- 当前冻结的是策略设置和股票范围，不是整个行情数据库版本；排队期间数据更新可能改变实际读取的数据。结果仍保留现有引擎的配置与审计证据。

## 新接口

| 接口 | 行为 |
| --- | --- |
| `POST /api/v1/backtest-jobs` | 202，创建任务；`kind` 为 `backtest` / `package` / `screen`，`request` 为对应原请求体 |
| `GET /api/v1/backtest-jobs` | 当前用户的活跃和最近任务，不返回配置快照 |
| `GET /api/v1/backtest-jobs/{id}` | 当前用户指定任务 |
| `POST /api/v1/backtest-jobs/{id}/cancel` | 取消排队或运行中的任务；已完成任务保持原结果 |
| `POST /api/v1/runs/archive` | `run_ids` 与 `archived`，最多 500 条；整批校验归属后处理 |
| `GET /api/v1/runs?archived=true` | 查询已归档记录；默认查询未归档 |

## 验证记录（2026-11-16）

- 41 项选定后端测试通过：任务归属与容量、取消/超时/进程崩溃后的名额释放、重启恢复、原有计算限制、真实子进程回测、提交配置快照、800 条导入、并发导入、超限拒绝、分页和归档恢复等。
- 其中真实任务队列执行了普通策略、300 只股票的规则策略及 800 只股票的条件回测。采用合成行情，不代表线上服务器或真实策略收益。800 只案例覆盖 180 个交易日，在本机测试约 14–20 秒；300 只案例覆盖 30 个回测交易日及预热数据，约 4 秒。
- 规则策略将每只股票重复执行的排序、复制、数值转换改为利用已有排序、整批转换。100/300/800 只股票的单次信号计算对照中，信号及得分一致，耗时约缩短至原来的三分之一。测试未推断线上性能。
- 前端 183 项测试通过，生产构建通过。
- 5 项依赖 HTTP TestClient 的既有测试因运行环境本地套接字创建受阻未完成；新接口业务逻辑通过直接调用和真实子进程测试覆盖。浏览器无法连接本地测试端口，实际页面交互与窄屏视觉验收仍待补做。

## 合并/上线前验收

1. 使用测试账户运行 300/800 只真实股票的目标策略，检查数据加载、回测、结果保存各阶段耗时和内存。
2. 运行期间切页、刷新、关闭再打开浏览器，确认状态可恢复，完成后结果可打开。
3. 验证取消、短超时、异常退出以及服务重启后，任务状态明确且可重新提交。
4. 导入 800 条有效代码，并混入重复和无效项；核对计数与数据库总数。超限时原股票池保持不变。
5. 批量归档与恢复，检查关联的审计、比较和模拟账户结果仍可读取。
6. 检查桌面及窄屏下任务卡片、导入报告、归档按钮及分页按钮。

合并与线上部署分别由用户操作；本次没有操作生产数据或部署。
